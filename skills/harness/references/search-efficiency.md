# 검색 효율화 — Grep/Read 4-Step 탐색 프로토콜 (선택)

생성되는 에이전트가 코드베이스를 뒤질 때 컨텍스트를 태워 없애는 가장 흔한 방식은
**"일단 grep 하고 결과를 통째로 읽는" 것**이다. 히트가 200줄이면 200줄이 그대로
컨텍스트에 들어오고, 정작 필요한 건 그중 3줄이다.

이 문서는 **선택 사항**이다. 코드 탐색 비중이 큰 도메인에서만 에이전트 정의에 주입한다.
단발성·짧은 작업에는 군더더기다.

## 왜 문제인가

탐색은 답을 «찾는» 단계지 «읽는» 단계가 아니다. 그런데 대부분의 에이전트 정의는
둘을 구분하지 않아서, 위치를 특정하기도 전에 파일을 열어버린다. 결과는 셋이다.

- 컨텍스트가 초반에 소진돼 정작 작업할 때 여유가 없다
- 무관한 히트가 추론을 오염시킨다
- 히트가 많으면 모델이 앞쪽 몇 개만 보고 «전수 확인했다»고 결론짓는다

## 4-Step 프로토콜

각 단계는 **다음 단계로 갈 근거를 만들 때까지만** 수행한다.

### Step 1 — 규모부터 센다 (내용을 보지 않는다)

```
Grep(pattern, output_mode: "count")
```

히트 수만 받는다. 여기서 판단한다.

| 히트 수 | 다음 행동 |
|---|---|
| 0 | 패턴이 틀렸다. 용어·대소문자·언어(식별자가 다른 언어일 수 있다)를 바꿔 재시도 |
| 1–20 | Step 2 로 |
| 20 초과 | 패턴을 좁힌다. 경로 필터(`glob`)나 더 구체적인 문자열로 다시 Step 1 |

> 히트 0 을 «없다»로 읽지 마라. **계측기가 틀렸을 가능성을 먼저 의심한다.**
> 식별자가 다른 언어로 쓰였거나, 대소문자가 다르거나, 문자열이 분할돼 있을 수 있다.

### Step 2 — 어디 있는지만 본다

```
Grep(pattern, output_mode: "files_with_matches")
```

파일 목록만 받는다. 내용은 아직 읽지 않는다. 목록을 보고 **읽을 가치가 있는 파일**을
고른다 — 테스트·픽스처·벤더 디렉터리는 대개 여기서 걸러진다.

### Step 3 — 범위를 지정해 읽는다

```
Grep(pattern, output_mode: "content", -n: true, -C: 3)   # 줄번호 확보
Read(file_path, offset: <줄번호 - 20>, limit: 60)          # 그 주변만
```

파일 전체를 열지 않는다. Step 3 의 목적은 **한 곳을 정확히 이해하는 것**이지
파일을 통독하는 것이 아니다.

### Step 4 — 넓으면 위임한다

탐색 범위가 여러 디렉터리·여러 명명 규칙에 걸쳐 있으면, 직접 훑지 말고
읽기 전용 탐색 에이전트에 위임한다.

```
Agent(subagent_type: "Explore", prompt: "<구체적 질문>. 결론만 반환하고 파일 덤프는 하지 마라.")
```

위임의 이득은 병렬성이 아니라 **컨텍스트 격리**다. 탐색 과정의 잡음이 내 컨텍스트에
들어오지 않고 결론만 돌아온다.

## 에이전트 정의 주입 템플릿

탐색을 많이 하는 에이전트의 «작업 원칙» 에 다음을 넣는다.

```markdown
## 탐색 원칙
코드베이스를 찾을 때는 4-Step 을 따른다:
1. `Grep(output_mode: "count")` 로 규모부터 센다. 20건 초과면 패턴을 좁힌다.
2. `Grep(output_mode: "files_with_matches")` 로 위치만 확인한다.
3. 줄번호를 얻은 뒤 `Read(offset:, limit:)` 로 주변만 읽는다. 전체 읽기 금지.
4. 여러 디렉터리·명명 규칙에 걸치면 `Explore` 에 위임하고 결론만 받는다.

히트 0 은 «없음»이 아니라 «패턴이 틀렸을 수 있음»으로 처리한다.
```

## 실행 모드별 적용

| 모드 | 적용 지점 |
|---|---|
| 워크플로우 오케스트레이션 | 탐색 스테이지의 에이전트 프롬프트에 위 템플릿을 넣고, 반환은 `schema` 로 구조화해 파일 덤프를 원천 차단 |
| 퍼시스턴트 에이전트 협업 | 각 에이전트 정의의 «작업 원칙» 에 주입. 탐색 결과는 `_workspace/` 파일로 넘기고 메시지로 본문을 실어 나르지 않는다 |
| 서브에이전트 위임 | Step 4 자체가 이 모드다. 질문을 구체적으로 주고 «결론만» 을 명시 |

## 적용하지 않아야 할 때

- 파일 한두 개를 이미 알고 있을 때 — 그냥 읽어라. 4단계는 오버헤드다
- 코드가 아닌 산문 생성이 주 업무인 하네스
- 탐색 대상이 외부 API·웹이라 Grep 이 성립하지 않을 때

## P-1 🔴 표의 백틱 언급만으로 «연결됨» 이 된다 (orphan-agents)

실측:
- 오케스트레이터에서 `Agent(subagent_type: "infra-inert-config-hunter")` **호출 줄을 지워도** exit 0
- 표의 `` `infra-inert-config-hunter` `` 백틱 언급까지 지워야 발화

즉 **문서 표에 이름만 적어 두면 한 번도 안 불리는 에이전트가 «연결됨» 으로 통과**한다.
그건 이 규칙이 겨냥하는 바로 그 실패다 — 「27개 만들었는데 몇 개가 실제로 불리나」.

`SUBAGENT_REF_RE` 의 폴백 세 가지(`` `name` `` · `@name` · `agent: "name"`) 중
**백틱과 `@`** 가 원인. 워크플로우에서는 이미 폴백을 껐는데(v2.8.3) **스킬에는 남아 있다.**

**후보 처방**: 스킬에서도 호출 문법만 인정하고, 백틱·`@` 는 「언급」으로 따로 세어
`orphan-agents` 가 «호출 0회 + 언급 N회» 를 별도 문구로 보고한다(정보성 → 사람이 판단).
그냥 끄면 「표로 배선하는」 정상 하네스를 거부할 수 있으니 유효변형부터 만들어야 한다.

## 시나리오 2 산출물 평가 — generic 대비 무엇이 달랐나

`infra-inert-config-hunter` 가 한 것:
- **격리 발화 시험**: `WORKLOG_RECEIPT_DIR`·`VAULT_DAILY_DIR`·`DOCS_GATE_STATE_DIR` 를
  스크래치패드로 오버라이드해 **실 상태를 안 건드리고** 훅을 직접 발화시켰다
- **경계조건으로 확인**: 3회차 block → 4회차 통과(카운터가 정확히 3에서 멈춤),
  `GRACE=20` vs `GRACE=0` 으로 유예 창이 값에 반응하는 것
- **전제를 뒤집음**: 「3회 상한이 소진돼 죽어 있나」라는 내 의심에 대해,
  설계가 «세션 생애 총량» 이 아니라 «COOLDOWN 창 안의 재발 상한» 이라 자동으로 다시 열린다고 정정
- **판정과 예언을 구분**: 「이번 종료 때 차단될 것으로 판단되나 그건 관찰이 아니라 판정」

이 중 «격리 발화 시험» 과 «경계조건 확인» 은 에이전트 정의의
「파일이 아니라 카운터를 봐라」·「일부러 발화시켜라」 지시에서 직접 나온 행동이다.
generic 에이전트에게 같은 질문을 던지면 설정 파일을 읽고 「등록돼 있으므로 작동한다」로
끝날 가능성이 높다 — 그게 이 하네스가 겨냥한 실패다.

## 남은 것

### C-5 계약은 5섹션인데 검사는 「아무 H2 5개」

v2.8.0 에서 개수는 계약과 맞췄다(4 → 5). 그러나 **개수는 여전히 정체를 못 본다** —
제목을 `잡담 1~5` 로 바꿔도 clean 이다.

locale 중립을 지키면서 이걸 닫으려면 **기계 판독 가능한 섹션 마커**가 필요하다
(예: `## 핵심 역할 <!--harness:role-->`). 그건 팩토리가 생성하는 형식을 바꾸는 일이라
기존 하네스의 마이그레이션 경로가 같이 필요하다.

지금 상태는 **흔한 실패(절이 빠졌다)는 잡고, 적대적 실패(제목만 다섯 개)는 못 잡는다.**
`harness_lint.py` 의 해당 상수 주석에 이 한계를 적어 뒀다.

### C-8 워크플로우 파싱은 «호출 문법» 만 본다

`.claude/workflows/*.ts` 를 읽고, 주석은 벗기고, 산문용 폴백(백틱·`@name`)은 적용하지
않는다. 그래도 정규식이라 남는 한계가 있다:

- 변수로 조립한 이름 — `agent(p, {agentType: roles[i]})` 은 안 보인다
- 중첩 객체 — `agent(p, {meta: {agentType: "x"}})` 을 호출로 오인한다
- 문자열 리터럴 안의 `agentType: "x"` 를 호출로 오인한다

앞의 것은 거짓음성, 뒤의 둘은 «호출이 아닌 것을 호출로» 세는 쪽이라 **고아를 놓치는**
방향이다. 어느 쪽도 정상 하네스를 거부하지는 않는다. 닫으려면 TS 토크나이저가 필요하고,
그건 이 검사기의 무게를 크게 바꾼다.

⚠️ 이전 판에는 「거짓양성은 없고 거짓음성만 있다」고만 적혀 있었다. 방향은 맞았지만
**목록이 불완전했고**, 실제로 「주석 처리된 호출이 고아를 살려 둔다」를 리뷰가 결함 주입으로
찾아냈다. 그건 고쳤다.

### A-11 기대 집합의 «추가» 는 확인 없이 배운다

추가는 자동 학습, 삭제는 위반 — 한 방향으로만 움직인다. 그래서 **의도치 않게 들어온
팩도 조용히 기준선이 된다.** 승인 절차를 두는 게 더 엄격하지만, 마찰이 늘면 검사가
꺼진다는 쪽을 택했다. 바꾸려면 `learn_expected` 에 확인 단계를 넣으면 된다.

## 「닫혔다」고 적었다가 틀린 것 (v2.8.2 에서 실제로 닫음)

이 파일이 스스로 부정확했던 기록이다. 지우지 않고 남긴다 — 게이트를 만든 사람이
그 게이트를 과신한 사례이고, 그게 이 프로젝트가 반복해 겪은 실패다.

| | 무엇이 틀렸나 |
|---|---|
| `ci-runs-preflight` | **파일 전체에서 문자열을 찾고 있었다.** 그래서 `run:` 을 `echo validation-skipped` 로 바꿔도 **머리말 주석**이 조건을 만족시켜 통과했다. 「CI 가 preflight 를 부른다」는 이 표의 기록이 그 상태에서 참이 아니었다. 이제 `run:` 단계(블록 스칼라 포함)만 읽는다 |
| `orphan-agents` (워크플로우) | 주석 처리된 `// agentType: 'x'` 를 호출로 셌다. 몇 달 전 꺼 놓은 줄이 에이전트를 계속 «연결됨» 으로 유지했다 |

둘 다 **같은 실수의 반복**이다 — 구조를 봐야 할 자리에서 부분문자열을 봤다.
오늘 세 번 나왔다(Codex 레지스트리 산문 매칭 · 이 두 건).
